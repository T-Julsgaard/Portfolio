# Facets and assembled stops (covers, buttons, cards, video, contact)

Deep reference for the assembled-stop system. **Read FACET-ASSEMBLY-MANUAL.md (repo root) FIRST** for the architecture/validation methodology; this doc holds the accumulated per-version behavior on top of it. Read both before touching facets, covers, stencil buttons, overlay cards, the in-scene video, or stop content.

## Stop info display: assemble mode, facets, covers, buttons, READ MORE (v23-v46)

**Stop info display** (v23, reworked v26–v27 — dev tools > "Stop Info" dropdown): `assemble` (default) or `panel` (the classic HTML overlay + clamped mouse-look, kept intact). In assemble mode a docked stop is a panorama of **facets** (text blocks / ASCII covers) hung at fixed yaws around the camera, **all at eye level** (v37 — anchor z = the camera's own z, pitch 0, so content sits where the scene is and the visitor never cranes); the visitor has free 360° drag-look (`freeYaw`/`freePitch`, street-view drag; scroll still departs, so panel-mode's drag-to-depart doesn't exist here). Each facet fires/releases on **yaw alone** (v37 — horizontal slices: fires within `F_GAZE_IN` ~23° of its compass direction, releases past `F_GAZE_OUT` ~35°; pitch never gates, so looking up or down cannot miss or drop content — with 360/7 ≈ 51.4° gallery spacing the ±23° fire windows can't overlap): its recruits fly staggered quadratic-bezier arcs, swap geometry mid-flight (shared `glyphGeo` cache), and settle as world-anchored content; **every other glyph in that facet's sight corridor is absorbed too** (flies into a random letter, fading only as it lands) — so content reads on pure black, and since v43 **nothing merely fades in place** (fade-in-place survives only as a budget-overflow fallback the raised budget makes unreachable). Partitioning happens once per dock (`assembleStop`): items exclusive per facet (nearest to its anchor, reading-order paired); **every** facet whose patch contains a glyph gets its own absorb record for it (v43 — was: corridor leftovers to the angularly nearest facet only) — gaze changes just replay cached flights, no per-frame searches. **The whole corridor joins the assembly (v40)**: pass 3 records EVERY glyph inside a facet's ellipse — other facets' owned letters included — for absorb flights staggered over the same window as the letter flights (budget `F_EXTRA_MAX` 9000 since v43, raised past the measured worst case ~7.2k members per corridor, validated against the real `asciiData`, so overflow never happens in practice). The near-field gate is `v.dot(F.dir)<0.2` (v43; was 1.2 in v41, 4 before) and each glyph's rim widens with proximity (`×(1+(10−vlen)·0.06)` under 10 units). **The sight cone (v43 — replaces scrapped v42's whole-foreground clearing; `v42.html` was deleted, its number stays burned)**: any glyph nearer than the content plane (`depth<dist+2`) and inside the content block's *exact angular footprint* (`coneY/coneP` = block half-extent + 0.06 rad — catches the rectangle's corners, which the inscribed ellipse missed, and glyphs right at the POV) always gets an absorb record, budget-exempt, on every facet type — nothing sits still or fades between the visitor and the text/image/buttons, while the background beyond the content is untouched (v42's mistake was clearing the whole ±60°/±49° facing view). **Facet-to-facet handoff (v43)**: absorb records are self-clocked (`rec.st`/`rec.mode`, animated in every non-`home` state, so a *holding* facet can still receive) and `m.userData.hold` names the facet currently animating a glyph, arbitrating every conflict. Because the gaze hysteresis makes a neighbor fire *before* the current facet releases, `facetOut` looks each departing glyph up in `stopFacets.byMesh` and, if an active facet has a record for it, launches that record (`launchAbsorb`) instead of the home flight — the old facet's letters fly *straight into* the new content instead of returning home and fading (items flag `handed` so their stale home flight can never resume). `facetIn` conversely steals from an `'out'`-state owner/holder mid-flight, and owners always reclaim their own letters (`facetIn` items clear `hold`). Departure (`disassemble`) passes `noHand=true` so everything genuinely flies home. Handed-off letters morph back to home geometry+color mid-flight; the receiver's landing/restore paths fully restore geometry (`rec.g0`), color and `userData.asm`, so a glyph can bounce A→B→A indefinitely. Ordinary stops have one facet dead ahead (auto-assembles on dock; layout via `buildStopLayout`). **v37 removed the whole facet-height machinery** — the per-direction needed-height (terrain clearance), the ~24° elevation cap and the gallery's shared ring height are gone; every anchor is simply eye level, and the elliptical clearing already guarantees legibility over any terrain. **Arrivals are continuous (v40, sealed v41)**: the flight itself blends the down-gaze up to the horizon over its last 30% (`levelQuat` slerp in the flying branch; the entering branch levels its target outright — assemble mode only, panel mode keeps the raw `poseAt` gaze), and `assembleStop` sets `freePitch=freePitchT=-pitch0` so the docked camera math starts exactly where the flight ended. `frame()` also caps dt at 50 ms: the gallery dock's heavy partition used to inflate one frame's dt and make the old arrival ease consume ~90% of its travel in a single step (the v39 "arrival snap"). v41 removed the last residual cut-over: `dock()` captures the exact touchdown pose (`dockT0`/`dockPos`/`dockQuat`) and the docked branch eases from it into its own pose math over 1.6 s (`dr` lerp/slerp) — so the flight's damped-follow lag, the `lookTX/lookTY` mouse sway and the idle breathing drift all fade in instead of switching on at full amplitude at flight end. (A dev-tools re-assemble while already docked sees `dr`=1, i.e. no blend.) The **clearing is elliptical, not rectangular** (v27): each facet fades/absorbs every glyph inside a jittered angular ellipse (`Ry/Rp` = block half-extent + 0.15 rad, per-glyph rim jitter + per-glyph fade rates via `fades[].k`), patches may overlap between facets (v43: every overlapping facet keeps its own absorb record; `userData.hold` decides who animates). Fade speed was retuned in v39 (`F_FADE_MS` 420→260, `k` floor 0.5→0.9) — the slowest glyphs used to linger visibly after the text had assembled. A stop with a `gallery:` array (the **Case studies** stop, waypoint xf-0.34/yf0.22) adds 6 ASCII covers ringing the visitor at **even 360/7 spacing** (earlier ±170° spread put buses/food only 20° apart), all level at eye height like every other facet (v37; the old shared max-zNeed ring is gone). `ASCII_COVERS` (~11KB) is generated **offline** by `gen_covers.py` (34-col grids, ramp `' .:-=+*#%@'`, bright paper covers auto-inverted so ink glows, cells colored by luminance via `setImgColor`). **v36 full-frame fill**: the three white-background covers (`vrchat`, `radiology`, `wegovy`) were regenerated so the *whole* frame is ASCII, not just the subject — earlier they mapped the white paper to spaces (empty), so the cover was subject-shaped and the develop into a rectangular photo looked wrong. The regen (from `images/*.png`, box-downsampled to the same cols×rows, inverted `val=1−L`, ramp index = `1 + round(val·8)` so the floor is `.` never space) fills the background with a faint dotted field while the darker subject still reads as denser/brighter glyphs. Same cols/rows/cw/ch, so layout is unchanged; the other covers (`networks`/`buses`/`food`/`buses_art`, already ~90–99% filled) were left byte-identical. Filling these three raises the gallery from ~5.3k to ~8k of the 13,268 glyphs — still well under the single-partition budget (`assembleStop` pass 2 claims all 7 facets at once from the shared pool). No standalone `gen_covers.py` in the repo; regenerate inline from `images/` if the source covers change. **The develop** (v27): ~0.45s after a cover finishes assembling (`PHOTO_DELAY`), the real front page fades in as an 8-column grid of textured tiles (`buildPhotoTiles`, staggered `PHOTO_STAGGER/TILE_MS`, placed 0.35 behind the glyph plane) while the image glyphs dissolve; the title stays as glyphs; looking away folds the photo up fast and everything scatters home (repeatable). Textures come from `COVER_PHOTOS` — **data-URI JPEGs (512px, ~320KB total, generated offline by `gen_photos.py`)**, because external image files would taint WebGL under file://. The bus cover (`ascii:'buses_art'`) assembles from the pre-made ascii-art variant before developing. Regenerate both embedded blocks after swapping cover images. **Cover layout & buttons (v37, reworked v39–v40)**: each gallery entry carries `tags`/`sub`/`blurb`/`pdf`/`more` alongside `img`/`title`. `buildCoverLayout` stacks (top→bottom): title (**always one line** — long titles auto-shrink from s 0.95 to fit ~23 units instead of wrapping) → subtitle (s 0.55) → the ASCII cover grid → blurb (s 0.55, wrap 48) → the button row. Tags do NOT appear on the cover (v40) — they render as chips in the READ MORE card only. Cover `hFit` is 1.25 (the fit math uses `BASE_FOV` 52 but the docked FOV is 80, so >1 is real headroom; this keeps the developed image at its v38 size, f=1.0 for all six covers). **Glyph budget is TIGHT (v41)**: the 5×7 stencils put the gallery at ~12.6k items + ~300 intro ≈ 12.9k of the 13,268 pool (~400 spare). Adding text to any cover (longer blurb/title/sub) can overflow the pool, which silently shorts the LAST-claimed cover (food) — validate with a quick Python count against `ASCII_COVERS` before shipping content edits. **Buttons are ASCII stencils (v40, refined v41)**: solid blocks of white `'#'` glyphs with the label (DOWNLOAD / READ MORE) punched out as holes, so the black letters are the background showing through — built from `BTN_FONT` (5×7 bitmap caps since v41, only the letters those labels need) on a `BTN_CELL` 0.19 grid, 1-cell padding, glyph scale cell×1.15 (any larger and the fill bleeds into the 1-cell hole strokes and swallows the letters — that killed the first v41 attempt at cell×1.5). Button items are flagged `btn:'pdf'|'more'` and `L:null` (they assemble from glyphs like all text and survive the photo develop); each button records a padded layout-space hit rect in `lay.btns`, which the facet copies (`F.btns`, each `{kind,cx,cy,hw,hh,items,hover}`; items collected in partition pass 2). `updateFacet` pulses settled button glyphs gray→white (`BTN_DIM` #a8a8a8 → `BTN_HOT` #fff, hover pins bright + pointer cursor; skipped when inverted), and the download button does one scale "pop" (`BTN_POP_DELAY` 1.5s after hold, `BTN_POP_MS` 450, ×1.3 sine — reads as a bold flash on the solid block) — scale writes only in 'hold' so flights are never fought. Clicking = a `pointerup` within 6 px of its `pointerdown`; `facetButtonHit` intersects the pointer ray with the facet plane and tests each rect: 'pdf' → `downloadPDF` (v43: `window.open(_blank)` — the report opens in its own tab instead of hijacking the site's tab; the READ MORE card's download link is `target="_blank"` too), 'more' → `showMore(F.g)` opens **the READ MORE card** (`#more-card`, an HTML side panel styled like `#panel`, left-center, z 7) with the project's Context/Methods/Outcomes (per-entry `more:{context,methods,outcomes}`, all English) plus a download link. The card closes on ×, Esc (checked before Esc-to-free-roam), the cover releasing (`facetOut` of any `F.g` facet), or `disassemble`; while open, the window `wheel` handler early-outs so reading can't charge a departure (the card itself stops wheel propagation and scrolls natively). (v59 removed the stop's bottom-left mini dock; the PDFs are reachable through the covers' DOWNLOAD buttons alone.) Budget: gallery needs ~5.3k of the 13,268 glyphs. `disassemble(true)` instant-restores everything (called from `beginIntro`, `genRun`, `assembleStop`); departure animates facets home via the `asmRetired` list. **The bottom-left mini dock is gone (v59, user request)**: in assemble mode `showStop` never shows the HTML panel at all (`#panel.mini` CSS remains but is never `.in`); stop `media:`/`links:` now surface only in the classic panel mode. Media images and PDFs live in `images/` and `pdfs/` (from the old `portfolio-main` site, which also supplied the stop content). The journey is now **6 stops** (v57: welcome, **Work experience**, **Education**, case studies, **Interests**, contact) — every retired stop's waypoint (incl. the old Orange Wheel stop, folded into Work experience) remains a plain path point, so the flight path is unchanged.

## v57: every stop is a facet gallery

**v57 — every stop is a facet gallery now.** The Case-studies machinery was generalized and rolled out to the rest of the journey; `gen_assets.py` methodology (scratchpad, offline) produced all new `ASCII_COVERS`/`COVER_PHOTOS` entries. What changed in the shared code, all in `buildCoverLayout`/`assembleStop`/`showMore`: gallery entries may omit `img` (**text-only facets** — bigger one-line title cap 1.30, no grid, no develop, `dist` ASM_DIST); `btns:[{t,kind,data}]` adds **custom stencil buttons** beside DOWNLOAD/READ MORE (BTN_FONT gained G I P S V Y); `href` makes a cover a **hyperlink mark** (no develop, `cap` caption line pulses as the affordance, one big kind-'link' hit rect over grid+caption); gallery ring spacing is now `360/(n+1)` with alternating ±1,±2,… placement (still max 6 gallery facets — spacing must exceed 2×F_GAZE_IN); `photoKey` is only set when `COVER_PHOTOS` actually has the key; `more.sections:[[h,t],…]` renders custom card headings (the classic context/methods/outcomes trio still works), plus `pdfLabel` and `link` ("Visit the website") on the card. Button dispatch (pointerup) gained kinds `chess` / `video` / `form` / `link` (mailto via location.href, else window.open _blank). The stops: **Work experience** (6 landscape logo "cards" — OW, Nordic Mining, Concentrix, Introtech, UNICEF, Artium+Brande Åbo combined — ASCII-impressionistic until the develop reveals the crisp logo; OW/Nordic/Concentrix carry READ MORE cards), **Education** (4 text-only facets; BSc diploma + tutor certificate are real DOWNLOAD buttons — those two PDFs were un-gitignored in v57 because the site serves them now), **Interests** (chess board cover + two piano-still covers; VIEW GAMES opens `#chess-card` — a full PGN replayer with a real legality engine (`cvMoves`/`cvSan`, SAN disambiguation needs legal-move filtering) stepping via buttons/arrows/wheel; `CHESS_GAMES` holds clearly-marked SAMPLE games awaiting Thomas's own PGNs; the two piano recordings — `videos/piano-1.mp4`/`piano-2.mp4`, 720p30 H.264 re-encodes of the iPhone HLG originals — merged in v61 into ONE facet that plays them IN-SCENE on a video plane; the `#video-card` overlay is gone — see the v61 paragraph), **Contact** (redesigned in v59 to ONE flipped facet — see the dedicated paragraph below; the octocat/LinkedIn marks are rasterized offline from the official SVG paths, subject-shaped, whole mark is the link; MESSAGE opens `#contact-card`, a fetch-POSTed Formspree form, endpoint `mbdlvnjo` from the old site; failure text points at plain email). The overlay cards (chess + contact since v61) share the `.ovl-card` skin, close on ×/Esc/`disassemble` (NOT on look-away — hostile mid-game), and hold the wheel (`ovlOpen()` guards the window handler; the chess card's own wheel steps moves). Glyph budgets validated against the real `asciiData` (scratchpad `validate.py`, replicates the layout counting + parses JOURNEY via esprima AST; re-run after v61's stencil titles/arrows): work ≈7.0k, interests ≈2.8k, edu ≈3.1k, contact ≈1.5k — case studies (≈12,965, ~300 spare) remains the binding worst case.

## v61: stencil typography, in-scene video, rotation arrows

**v61 — stencil typography, in-scene video, rotation arrows.** Four coupled changes. (1) **Typography**: `BTN_FONT` grew to the full A–Z, digits 0–9 and `. , ' - & ? ! : ( ) /`, with helpers `stGlyph`/`stCols`/`stFill` (metrics/fill counts) and `layStencilLine(items,t,cell,x0,yTop,extra)` (lays one line of positive `'#'`-cell stencil letters; `extra` merges btn/nav/wd metadata). **Every facet title now renders in this stencil face** (uppercased, cell shrinks to fit): `buildStopLayout` (cell ≤0.27), `buildCoverLayout` (≤0.16 with a grid, ≤0.20 text-only), `buildContactLayout` (0.20) and the welcome title "HI, I'M THOMAS." (0.20). **Exception: case-study cover titles stay plain one-liners** (`buildCoverLayout(g,plainTitle)`, passed as `st.id==='cases'`) — at ~16 glyphs/char the six long Danish paper titles would add ~3k items and blow the 13,268 pool, and the cells would be unreadably small. Body text got tighter: `ASM_ADV` 0.78→0.68. (2) **Welcome**: the "SECTIONS" header is gone (labels are their own affordance; nav waves renumbered 0-based, list rides 0.5u above centre on the figure), and the commit banner is now a **stencil stream**: `startBannerWrite` lays the message in `BTN_FONT` cells (cell ≤0.15, shrinks to the calendar width) and each cell self-clocks off its stencil column — assemble at `col·WB_COL` (22ms), linger `WB_LINGER` (3400ms — deliberately longer than the longest message's sweep so every stat is briefly readable whole), then stream home; the head of a message dissolves while its tail is still arriving, one continuous character stream (`phase 'stream'` replaced write/hold/clear). The banner reserve is sized from the actual messages (`max(stFill)+8` ≈ 300–450 glyphs, was a fixed 30) — fine at welcome's ~2.4k usage. (3) **In-scene video** (the Interests stop): the two piano entries merged into ONE facet with `vids:[{src,ascii},…]` + `imgScale:1.6` (the still — and thus the video — renders 1.6× a standard cover; grid pitch scaling in `buildCoverLayout`). The `#video-card` overlay is deleted; `PLAY` (`kind:'vplay'` → `facetPlayVideo`) builds a **world-anchored video plane** (`buildVideoPlane`, THREE.VideoTexture, 0.35 behind the glyph plane, exactly the grid area, stationary like the photo tiles), starts the video immediately, dissolves the ASCII cells under it and pauses the music bar (`musicHold`/`musicRelease` via `#m-play`, mirroring the old overlay's truthful-state trick); PLAY again toggles pause; video end rests on the last frame (no fold — that would be a fade-in-place to undo); look-away (`facetOut`) folds the plane and pauses; `disposeFacetTiles` also disposes the plane. Under `file://` (tainted WebGL) vplay falls back to `window.open` of the raw file. The **next-arrow** (`VNEXT_ART` chevron right of the grid, `kind:'vnext'` → `facetNextVideo`) folds any playing video, advances `vIdx`, rewrites `it.geoA/it.L` from the next `ascii` grid (both piano grids are 34×16, fully filled — 1:1 cell mapping via `it.gr`, threaded through pass 2) and launches self-clocked morph flights (`F.vSwap`, animated in `updateFacetVideo`, swept L→R by column): cells that were developed away WRITE in from their terrain homes, visible cells do an out-and-back arc morphing at the apex. `renderDirty` is forced every frame the plane is visible (a playing video must never hold the last render). (4) **Rotation-hint arrows**: on every multi-facet stop (`defs.length>1` — welcome/contact are single-facet and skip by the same rule) each facet is flanked by a mirrored pair of ramp-shaded ASCII arrows (`ROT_ARROWS`, three designs: `stream`/`wedge`/`dart`, dev panel ▸ Journey ▸ "Rotation arrows", `arrowSelect` in CTRL_DEF, default `stream`, `'off'` available; `layArrowArt` lays them like the gh/li marks — luminance-shaded cells; `addFlankArrows` appends them to a finished layout and grows `lay.w` so the clearing ellipse covers them). Clicking one (`kind:'rotl'/'rotr'` → `rotateDock(±1)`) turns `freeYawT` a whole facet step (+1 = left, matching the yaw math). **Case-studies covers skip the arrows** (intro facet only): that stop runs ~12,965 of 13,268 with the stencil stop-title included (~300 spare — revalidate in Python before adding ANY content there). Arrow/vnext button cells keep their luminance shading in the pulse loop (`isArt` branch — base shade + gentle glow, hover lifts toward white) instead of the flattening gray→white stencil-button pulse.

## Contact stop: one flipped facet (v59)

**Contact stop — one flipped facet (v59).** The contact stop's 3-facet ring (GitHub / LinkedIn / Write-me) is gone; everything now shares ONE facet, and it hangs **behind** the arrival direction so the docked view reads against the face the journey just crossed instead of the void past the chin. Two orthogonal mechanisms, both generic: (1) **`flip:true`** on a stop makes `assembleStop` add π to `yaw0` (the whole panorama rotates — every dy is relative to it), and `dock()` — *after* `assembleStop`, which still zeroes `freeYaw` — sets `freeYaw=-Math.PI` so the camera still touches down facing down-path (seamless with every travel style) and the ordinary docked yaw smoothing pans it one half-turn around to the content, riding the same 1.6 s `dr` arrival blend (mid-pan the face sweeps by while the letters fly in). Only real arrivals pan; a dev re-assemble while docked calls `assembleStop` directly and just snaps. The slerp is never ambiguous: the gap to `dockQuat` only *approaches* π as `freeYaw` decays, so the quaternion dot stays positive. (2) **`contact:{marks:[{img,href}],btns:[{t,kind,data}]}`** on the stop routes facet 0 through `buildContactLayout` (hFit 0.80): title + wrapped body (both `chBase`-baseline-corrected), then the marks side by side at `CONTACT_MARK_S` 0.55 of their cover pitch (≈5 units tall vs the old 9 — sized to share one view), each with a whole-mark `kind:'link'` hit rect and NO caption/title text (the pointer cursor is the affordance; mark cells are NOT flagged `btn`, so the button pulse never flattens their luminance shading), then the MESSAGE/EMAIL stencil row via `layBtnRow` — the button-row builder extracted byte-identical out of `buildCoverLayout` so both share it. No develop, no READ MORE. Budget ≈1.4k items (validated against the real `ASCII_COVERS`/`BTN_FONT`). Auto tour: single-facet stops don't sweep, so contact just dwells, unchanged. Panel mode ignores all of this (no facets, unflipped `poseAt` gaze). Verified headless (CDP): pan lands on the assembled facet, marks open their URLs, MESSAGE opens the form, an exact 180° drag-behind shows the void that used to be dead ahead.
