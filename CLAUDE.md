# Portfolio 2.0 — ASCII Portrait Site

A single-file, no-build Three.js prototype: an interactive ASCII-art portrait (13,268 glyphs) the visitor can fly through. No framework, no bundler — everything lives in one HTML file.

The portrait data (as of v18) is a direct Grainrad ASCII generator export (172×157 grid, standard charset `.:-=+%#@*`, all-white). The 19 frames in `PROGRESSIVE_FRAMES` (34 → 3,791 glyphs, coarse → fine) drive the "Progressive" load animation; unlike the pre-v18 set (which came from Grainrad itself), they are generated offline by downsampling the embedded `asciiData` onto coarser grids (5 → 64 columns, representative glyph per cell = fine glyph nearest the cell centre, cell z = mean depth) — so a portrait swap requires regenerating them from the new data. Bounds/constants (`centerX/Y`, `spanX/Y`, `midZ`, `farDist`, fog, the journey path and its terrain heightmap) are all derived from the embedded `asciiData`, so swapping the portrait data automatically re-scales the whole scene. Glyph geometry is cached per unique character (`glyphGeo`) and shared across all instances — required at this glyph count — with a dash fallback for symbols the helvetiker font lacks (`∏ ∑ √ ÷ ≠ ≥ ≤ ×`). Since v28 the geometry is a flat `ShapeGeometry` (same font outlines the old extruded TextGeometry used; the 0.02 extrusion was invisible on billboarded unlit glyphs and doubled the triangle count).

**Rendering architecture (v29 — instanced pools).** The 13,268 glyphs are NOT individual meshes anymore (they were through v28, which was the old-hardware bottleneck: 13k draw calls + per-object matrix/cull/sort work every frame). Each unique character owns one `InstancedMesh` (a "pool", 9 for the portrait charset, more created lazily for assembled stop text); a glyph is a lightweight `Glyph` proxy `{position, scale, visible, material:{color,opacity}, geometry, userData}` holding a slot in a pool, so all animation code manipulates proxies exactly like the old Meshes. Assigning `.geometry` (the facets' mid-flight character swap) moves the glyph between pools. `syncPools()` rewrites the instance buffers only on frames where glyph state changed (`glyphsDirty` — every animation path sets it; a missed path shows up as glyphs frozen until the next dirty frame, so set it when adding new animations). Billboarding is free: instance matrices carry translation+uniform-scale only and the camera quaternion (`BB_UNIFORM`/`uBB`, one shared uniform) rotates glyph vertices in the vertex shader via `GLYPH_MAT.onBeforeCompile` (which also adds the per-instance `instanceOpacity` attribute; per-instance color rides the built-in `instanceColor`). All pools share the single `GLYPH_MAT`; pool geometry is a *clone* of the `glyphGeo` cache entry because the generator preview still uses the cache geometry on plain Meshes. Photo tiles get `renderOrder=-1` (draw before the pools) to preserve the old per-mesh depth-sort behavior during the develop. A `renderDirty` flag forces repaints for non-camera changes (dev sliders, invert/raw, generator); a fully settled overview skips rendering identical frames. Known acceptable deviation: overlapping *semi-transparent* glyphs blend in pool/slot order rather than exact depth order, visible only mid-animation on black — the settled scene is unaffected. The generator preview (`genPreviewMeshes`) still uses plain Meshes.

**Load animations** (selectable in dev tools, replayable): `progressive-soft` (default, v22 — same coarse→fine ramp, but instead of the final hard cut the 13k real glyphs dissolve in individually over ~2.2 s, staggered with a slight peaks-first bias, while the held last frame melts away underneath; the camera push-in spans the whole run so the finish has no jump), `progressive` (the original ramp — resolves through the 19 frames, then snaps to the full portrait; the snap is a ~3.5× density jump, which is why the soft variant exists) and `surface` (the ember/parallax reveal: glyphs surface out of the relief, igniting hot then cooling, while the camera arcs from a close 3/4 angle out to the overview). `beginIntro(mode)` is the single entry point.

**Music bar** (v30; playlist grown to 78 tracks in v32): a minimal fixed pill in the top-right corner (`#music`, styled like the journey buttons — 10px uppercase mono, hairline border, blur backdrop) streaming the playlist through a hidden 2×2 YouTube IFrame player (`#yt-audio-wrap`). It's a self-contained plain `<script>` IIFE just before the main module — playlist lives in its `TRACKS` array (id + "Artist — Title" label; adding a song is genuinely plug-and-play — append one entry, the bar auto-skips any that turn out embed-disabled). New batches are parsed offline from a links markdown and oEmbed-checked for dead/private IDs before insertion. UI: 4-bar CSS equalizer (animates when `.playing`, staggered opacity pulse while `.wait`ing for the stream), marquee title (ping-pong `--mq`/`--mqd`, only when the label overflows 172px; the title is a link to the video on YouTube), prev (restarts after 3 s, classic behavior), play/pause, next, and volume (slider expands on hover; scrolling anywhere on the bar nudges volume and flashes the slider via `.volshow` — `stopPropagation` keeps it from charging the journey departure; window pointer handlers already ignore non-canvas targets). The IFrame API script preloads at startup but the embed is only created when playback first starts, so autoplay-with-sound rides the gesture + `allow="autoplay"` delegation; track end auto-advances, embed-blocked videos are skipped (label "stream unavailable — press play to retry" after a full failed cycle; play resets the streak), and volume persists in `localStorage` (`pf_music_vol`; **default 25%** when unset). **Autostart** (v33, reworked v35): browsers block *audible* autoplay without a user gesture but always allow *muted* autoplay, so v35 begins playback **muted the instant the page loads** (`setTimeout(autostart,0)` — the equalizer runs, the clock ticks) and **unmutes on the visitor's first interaction**. `effMute() = muted || !engaged` gates every mute/unmute (onReady + `applyVolume`); the first-interaction path (`engage()`) flips `engaged` and unmutes+plays. `engage` is armed as one-shot capture listeners on `mousemove`/`pointerdown`/`keydown`/`wheel`/`touchstart` — `mousemove` is included so on this cursor-driven page the music usually goes audible the moment the mouse moves; the discrete gestures are the reliable fallback since some browsers pause a script-unmuted clip that had no *activating* gesture (mousemove/wheel don't grant activation) — `engage()` is idempotent so the imminent click/scroll recovers it. All paths early-out on the `file://`/failed state. **Playlist order is user-editable** (v35): dev tools ▸ "Playlist order…" opens a compact drag-to-reorder modal (`#playlist-modal`, built in the IIFE, list of all 78 tracks with grip/number/label, drop-below-lands-after semantics); the order persists in `localStorage` (`pf_music_order`, array of ids — unknown ids dropped, newly-added tracks appended so it survives playlist growth), applied over the live `TRACKS` in place at startup. `MASTER` snapshots the original curated order for the modal's "Reset order". Reordering keeps `idx` pinned to the now-playing track by id. The Begin journey/Free roam buttons moved down one slot (top 53/89) to give the bar the corner. **YouTube refuses ALL embeds on `file://` pages** (error 153, empty referer — verified per-track in headless Chrome, v31): music cannot work when index.html is double-clicked, only when served over http(s). The bar detects this (`location.protocol==='file:'` in `onError`) and labels itself "file:// blocks streaming — use open portfolio.bat"; `open portfolio.bat` (repo root) starts `python -m http.server 8123` minimized and opens `http://localhost:8123/` — the double-click way to browse the site with working music. The deployed/hosted site is unaffected.

## Files

- `index.html` — always the current/latest version. Open this directly in a browser.
- `v1.html` … `vN.html` (repo root) — frozen snapshots, one per round of changes. **Never overwrite an existing version.** When making a new change: save the result as the next `vN.html`, then copy that same file over `index.html`.
- `site.html` (repo root) — a stray leftover from an early preview auto-save, predates the versioning convention. Not part of the versioning chain; safe to ignore/delete.

No `git` repo — versioning is done purely via these numbered files.

## How the scene works

Bounds/derived constants are computed once from the embedded `asciiData` JSON (13,268 `{x,y,z,char}` instances): `centerX/Y`, `spanX/Y`, `midZ`, `farDist`. Glyph grid spacing is `0.6` (x) × `1.0` (y) — used wherever code needs real neighbor/row adjacency.

**The journey** (v20+, replaces the old "descend through the portrait" model): the portrait is treated as terrain (glyph z = relief height). A centripetal Catmull-Rom path snakes over the face through 20 waypoints (10 of them exhibit stops), altitude = local terrain max (`terrainH`, ±5×±3-cell window over `TERRAIN` heightmap) + `JCLEAR` (default 7), passed through a ±9-sample moving max (climb *before* hills) and 3 box-smooth passes, clamped to never dip below the safe height — collision-free by construction (validated numerically against the data). `pathPos(s)` is arc-length parameterized; `poseAt(s)` gazes `LOOK_AHEAD_U` (16 units) down-path with pitch clamped to ~11°–30° so every stop frames the landscape consistently. Content lives in the `JOURNEY` array (marked `EDIT YOUR CONTENT HERE`): per stop `{id,label,title,body,media:[{src,caption}],links:[{href,label}]}`.

**UI state machine** (`uiState`):
- `overview` — free orbit via `OrbitControls`, as before.
- `entering` — flies from the current camera pose to a stop's pose (duration scales with distance).
- `journey` — two sub-modes (`jMode`): `docked` (holding a stop: idle breathing drift, hint visible; in assemble mode free 360° drag-look + facet firing, scroll charges the departure bar; in panel mode the classic damped mouse-look ±~30°/±17° where drag *or* scroll charges departure; 650 ms dock cooldown swallows trackpad inertia) and `flying` (eased arc-length flight along the path, damped quaternion follow, slight FOV stretch). Rail dots and arrow keys also travel; Esc exits to free roam; scrolling past either end gives a soft rebuff bounce.
- `exiting` — **Free roam** button; returns to the overview framing and re-enables OrbitControls.

**Stop info display** (v23, reworked v26–v27 — dev tools > "Stop Info" dropdown): `assemble` (default) or `panel` (the classic HTML overlay + clamped mouse-look, kept intact). In assemble mode a docked stop is a panorama of **facets** (text blocks / ASCII covers) hung at fixed yaws around the camera, **all at eye level** (v37 — anchor z = the camera's own z, pitch 0, so content sits where the scene is and the visitor never cranes); the visitor has free 360° drag-look (`freeYaw`/`freePitch`, street-view drag; scroll still departs, so panel-mode's drag-to-depart doesn't exist here). Each facet fires/releases on **yaw alone** (v37 — horizontal slices: fires within `F_GAZE_IN` ~23° of its compass direction, releases past `F_GAZE_OUT` ~35°; pitch never gates, so looking up or down cannot miss or drop content — with 360/7 ≈ 51.4° gallery spacing the ±23° fire windows can't overlap): its recruits fly staggered quadratic-bezier arcs, swap geometry mid-flight (shared `glyphGeo` cache), and settle as world-anchored content; **every other glyph in that facet's sight corridor is absorbed too** (flies into a random letter, fading as it lands, budget `F_EXTRA_MAX` 2200) **or fades in place** — so content reads on pure black (this replaced the v23 dim-to-0.15). Partitioning happens once per dock (`assembleStop`): items exclusive per facet (nearest to its anchor, reading-order paired), corridor leftovers to the angularly nearest facet — gaze changes just replay cached flights, no per-frame searches. **The whole corridor joins the assembly (v40, supersedes v38's fade-only rule for owned glyphs)**: pass 3 absorbs EVERY glyph inside a facet's ellipse — other facets' owned letters included — into flights staggered over the same window as the letter flights (budget `F_EXTRA_MAX` 4500; only overflow just fades). Owned records carry `own` (their owner facet) and every animation path (`facetIn`/`facetOut`/`updateFacet`'s extras loop/`restoreFacet`) cedes the glyph the moment `own.state!=='home'`, so an absorb never fights the owner's flights or assembled text; the absorber also keeps a fade entry with an `ex` back-ref (the fade pass skips while that absorb flight is running) so a glyph the owner hands back home later melts out of the cleared patch again. Ordinary stops have one facet dead ahead (auto-assembles on dock; layout via `buildStopLayout`). **v37 removed the whole facet-height machinery** — the per-direction needed-height (terrain clearance), the ~24° elevation cap and the gallery's shared ring height are gone; every anchor is simply eye level, and the elliptical clearing already guarantees legibility over any terrain. **Arrivals are continuous (v40)**: the flight itself blends the down-gaze up to the horizon over its last 30% (`levelQuat` slerp in the flying branch; the entering branch levels its target outright — assemble mode only, panel mode keeps the raw `poseAt` gaze), and `assembleStop` sets `freePitch=freePitchT=-pitch0` so the docked camera math starts exactly where the flight ended — zero post-dock re-aim. `frame()` also caps dt at 50 ms: the gallery dock's heavy partition used to inflate one frame's dt and make the old arrival ease consume ~90% of its travel in a single step (the v39 "arrival snap"). The **clearing is elliptical, not rectangular** (v27): each facet fades/absorbs every glyph inside a jittered angular ellipse (`Ry/Rp` = block half-extent + 0.15 rad, per-glyph rim jitter + per-glyph fade rates via `fades[].k`), patches may overlap between facets (fades shared, absorb-flights exclusive to the angularly nearest). Fade speed was retuned in v39 (`F_FADE_MS` 420→260, `k` floor 0.5→0.9) — the slowest glyphs used to linger visibly after the text had assembled. A stop with a `gallery:` array (the **Case studies** stop, waypoint xf-0.34/yf0.22) adds 6 ASCII covers ringing the visitor at **even 360/7 spacing** (earlier ±170° spread put buses/food only 20° apart), all level at eye height like every other facet (v37; the old shared max-zNeed ring is gone). `ASCII_COVERS` (~11KB) is generated **offline** by `gen_covers.py` (34-col grids, ramp `' .:-=+*#%@'`, bright paper covers auto-inverted so ink glows, cells colored by luminance via `setImgColor`). **v36 full-frame fill**: the three white-background covers (`vrchat`, `radiology`, `wegovy`) were regenerated so the *whole* frame is ASCII, not just the subject — earlier they mapped the white paper to spaces (empty), so the cover was subject-shaped and the develop into a rectangular photo looked wrong. The regen (from `images/*.png`, box-downsampled to the same cols×rows, inverted `val=1−L`, ramp index = `1 + round(val·8)` so the floor is `.` never space) fills the background with a faint dotted field while the darker subject still reads as denser/brighter glyphs. Same cols/rows/cw/ch, so layout is unchanged; the other covers (`networks`/`buses`/`food`/`buses_art`, already ~90–99% filled) were left byte-identical. Filling these three raises the gallery from ~5.3k to ~8k of the 13,268 glyphs — still well under the single-partition budget (`assembleStop` pass 2 claims all 7 facets at once from the shared pool). No standalone `gen_covers.py` in the repo; regenerate inline from `images/` if the source covers change. **The develop** (v27): ~0.45s after a cover finishes assembling (`PHOTO_DELAY`), the real front page fades in as an 8-column grid of textured tiles (`buildPhotoTiles`, staggered `PHOTO_STAGGER/TILE_MS`, placed 0.35 behind the glyph plane) while the image glyphs dissolve; the title stays as glyphs; looking away folds the photo up fast and everything scatters home (repeatable). Textures come from `COVER_PHOTOS` — **data-URI JPEGs (512px, ~320KB total, generated offline by `gen_photos.py`)**, because external image files would taint WebGL under file://. The bus cover (`ascii:'buses_art'`) assembles from the pre-made ascii-art variant before developing. Regenerate both embedded blocks after swapping cover images. **Cover layout & buttons (v37, reworked v39–v40)**: each gallery entry carries `tags`/`sub`/`blurb`/`pdf`/`more` alongside `img`/`title`. `buildCoverLayout` stacks (top→bottom): title (**always one line** — long titles auto-shrink from s 0.95 to fit ~23 units instead of wrapping) → subtitle (s 0.55) → the ASCII cover grid → blurb (s 0.55, wrap 48) → the button row. Tags do NOT appear on the cover (v40) — they render as chips in the READ MORE card only. Cover `hFit` is 1.25 (the fit math uses `BASE_FOV` 52 but the docked FOV is 80, so >1 is real headroom; this keeps the developed image at its v38 size, f=1.0 for all six covers — validated against the embedded data, gallery total ~11.2k items of the 13,268 pool). **Buttons are ASCII stencils (v40)**: solid blocks of white `'#'` glyphs with the label (DOWNLOAD / READ MORE) punched out as holes, so the black letters are the background showing through — built from `BTN_FONT` (4×5 bitmap caps, only the letters those labels need) on a `BTN_CELL` 0.26 grid, 1-cell padding, glyph scale cell×1.5 for solidity. Button items are flagged `btn:'pdf'|'more'` and `L:null` (they assemble from glyphs like all text and survive the photo develop); each button records a padded layout-space hit rect in `lay.btns`, which the facet copies (`F.btns`, each `{kind,cx,cy,hw,hh,items,hover}`; items collected in partition pass 2). `updateFacet` pulses settled button glyphs gray→white (`BTN_DIM` #a8a8a8 → `BTN_HOT` #fff, hover pins bright + pointer cursor; skipped when inverted), and the download button does one scale "pop" (`BTN_POP_DELAY` 1.5s after hold, `BTN_POP_MS` 450, ×1.3 sine — reads as a bold flash on the solid block) — scale writes only in 'hold' so flights are never fought. Clicking = a `pointerup` within 6 px of its `pointerdown`; `facetButtonHit` intersects the pointer ray with the facet plane and tests each rect: 'pdf' → `downloadPDF` (temporary `<a download>` click), 'more' → `showMore(F.g)` opens **the READ MORE card** (`#more-card`, an HTML side panel styled like `#panel`, left-center, z 7) with the project's Context/Methods/Outcomes (per-entry `more:{context,methods,outcomes}`, all English) plus a download link. The card closes on ×, Esc (checked before Esc-to-free-roam), the cover releasing (`facetOut` of any `F.g` facet), or `disassemble`; while open, the window `wheel` handler early-outs so reading can't charge a departure (the card itself stops wheel propagation and scrolls natively). The stop's mini dock keeps the six HTML PDF links as before. Budget: gallery needs ~5.3k of the 13,268 glyphs. `disassemble(true)` instant-restores everything (called from `beginIntro`, `genRun`, `assembleStop`); departure animates facets home via the `asmRetired` list. The HTML panel drops to a `mini` bottom dock with media thumbnails + link buttons (the gallery stop carries all six report PDFs there). Media images and PDFs live in `images/` and `pdfs/` (from the old `portfolio-main` site, which also supplied the stop content). The journey is now **7 stops** (welcome, profile, Orange Wheel, startups, case studies, skills, contact) — the old separate case stops' waypoints remain as plain path points, so the flight path is unchanged.

**Stop markers: none** (removed across v24–v25 at the user's request as wayfinding clutter). The v20 beacon system — numbered text plaques *and* the additive light pillars/beams — plus the breadcrumb path dots are all gone, along with their helpers (`makeSignTexture`, `roundRectPath`, `pickPlaque`/the plaque raycaster, `buildCrumbs`, `buildBeacons`, `syncJourneyPalette`, `BEAM_TEX`) and the "Path dots" dev toggle. **The flight path itself is unchanged** — only the visual overlays came off. Arrival at a stop is announced solely by the assembled text (or the HTML panel); stops are reached via scroll/drag, arrow keys, and the rail list.

**Intro reveal** (the `surface` load animation): on load, all glyphs start at scale 0. A multi-seed flood fill (Game-of-Life-style, 8-neighbor Moore neighborhood over the real sparse grid, randomized branch order + jitter + occasional early "sparks") assigns each glyph a delay, so the portrait spawns into existence organically rather than as a uniform ripple. Runs once, self-terminates. (The default load animation is now `progressive-soft` — see the intro/animation notes above.)

**Journey FOV/bloom automation** (v33, retuned v34): a factor `journeyT` (0 in free roam … 1 at a stop) drives FOV widen `BASE_FOV`→`JOURNEY_FOV` (52→80) and bloom fade-to-0, applied in one place at the end of `frame()`. **v34 fix**: journeyT is no longer an independent exponential smoother — that ran fastest at t=0, so the FOV widened *before* the ease-in camera dolly began moving, which read as a zoom-out-then-in. Instead each state branch sets journeyT from *its own* eased transition progress: entering `journeyFrom+(1-journeyFrom)*ek`, exiting `journeyFrom*(1-ek)`, steady overview/journey pinned to 0/1. So FOV+bloom ride the exact same `easeInOut(k)` curve as the enter/exit camera move — slow at both ends, synchronized. `journeyFrom` (captured in `beginEnter`/`beginExit`) keeps an interrupted/reversed transition continuous. The dev bloom sliders write a separate `baseBloom` object (the overview target); the live pass is `bloom.* = baseBloom.* * (1 - journeyT)`, so sliders and automation never fight — free roam shows the slider values, a docked stop shows zero. The four per-state `camera.fov=…` writes were collapsed into this one (flight's `fovBoost` hoisted). Since journeyT only changes during entering/exiting (states that always render), the overview idle-skip needs no special-casing.

**Dev tools**: gear icon (bottom-left) opens a panel for live-tweaking bloom strength/radius/threshold, FOV, fog near/far, vignette toggle, journey **Path Height** (rebuilds the path live), **Load Animation** and **Stop Info** dropdowns. (Bloom/FOV sliders feed the automation above — see that note.) A **Raw (no processing)** toggle (v19) bypasses every layer added on top of the grainrad export — the whole EffectComposer/bloom path (frame loop falls back to `renderer.render`), ACES tone mapping, fog (`scene.fog=null`; `sceneFog` keeps the tuned object), vignette, and the `#e8ecf3` tint (pure `#ffffff` instead) — reproducing the raw generator scene's look. The composer renders into a 4× multisampled half-float target, because EffectComposer otherwise drops canvas MSAA and visibly aliases glyph edges.

## Conventions from this project's history

- Always validate camera-math/data-dependent changes (distances, fog thresholds, grid spacing, flood-fill reachability) against the real embedded `asciiData` using a quick script before shipping (Node is not installed on this machine; Python 3.11 is available as `python`). JS syntax can be checked with the `esprima` pip package.
- The file CAN be browser-tested from here (since v28/v29): `.claude/launch.json` defines a `portfolio-static` config (`python -m http.server 8123`; `portfolio-static-8124` is a fallback for when another session holds 8123) for the Claude preview tools — navigate to `/vN.html`, check console logs, screenshot, and drive the journey by clicking `#enter-btn`/rail dots and dispatching PointerEvents on the canvas. Caveats: WebGL there is software-rendered and the hidden tab throttles rAF to ~1/s between tool calls, so animation-timing/FPS observations are unreliable — use it for correctness and settled-state visual parity, not performance numbers.
- Still report clearly what to check when the user opens changes in a real browser (real-GPU behavior, animation feel and frame rate can only be judged there).
