# Portfolio 2.0 — ASCII Portrait Site

A single-file, no-build Three.js prototype: an interactive ASCII-art portrait (13,268 glyphs) the visitor can fly through. No framework, no bundler — everything lives in one HTML file.

The portrait data (as of v18) is a direct Grainrad ASCII generator export (172×157 grid, standard charset `.:-=+%#@*`, all-white). The 19 frames in `PROGRESSIVE_FRAMES` (34 → 3,791 glyphs, coarse → fine) drive the "Progressive" load animation; unlike the pre-v18 set (which came from Grainrad itself), they are generated offline by downsampling the embedded `asciiData` onto coarser grids (5 → 64 columns, representative glyph per cell = fine glyph nearest the cell centre, cell z = mean depth) — so a portrait swap requires regenerating them from the new data. Bounds/constants (`centerX/Y`, `spanX/Y`, `midZ`, `farDist`, fog, the journey path and its terrain heightmap) are all derived from the embedded `asciiData`, so swapping the portrait data automatically re-scales the whole scene. Glyph geometry is cached per unique character (`glyphGeo`) and shared across all instances — required at this glyph count — with a dash fallback for symbols the helvetiker font lacks (`∏ ∑ √ ÷ ≠ ≥ ≤ ×`).

**Load animations** (selectable in dev tools, replayable): `progressive-soft` (default, v22 — same coarse→fine ramp, but instead of the final hard cut the 13k real glyphs dissolve in individually over ~2.2 s, staggered with a slight peaks-first bias, while the held last frame melts away underneath; the camera push-in spans the whole run so the finish has no jump), `progressive` (the original ramp — resolves through the 19 frames, then snaps to the full portrait; the snap is a ~3.5× density jump, which is why the soft variant exists) and `surface` (the ember/parallax reveal: glyphs surface out of the relief, igniting hot then cooling, while the camera arcs from a close 3/4 angle out to the overview). `beginIntro(mode)` is the single entry point.

## Files

- `index.html` — always the current/latest version. Open this directly in a browser.
- `v1.html` … `vN.html` (repo root) — frozen snapshots, one per round of changes. **Never overwrite an existing version.** When making a new change: save the result as the next `vN.html`, then copy that same file over `index.html`.
- `site.html` (repo root) — a stray leftover from an early preview auto-save, predates the versioning convention. Not part of the versioning chain; safe to ignore/delete.

No `git` repo — versioning is done purely via these numbered files.

## How the scene works

Bounds/derived constants are computed once from the embedded `asciiData` JSON (13,268 `{x,y,z,char}` instances): `centerX/Y`, `spanX/Y`, `midZ`, `farDist`. Glyph grid spacing is `0.6` (x) × `1.0` (y) — used wherever code needs real neighbor/row adjacency.

**The journey** (v20+, replaces the old "descend through the portrait" model): the portrait is treated as terrain (glyph z = relief height). A centripetal Catmull-Rom path snakes over the face through 20 waypoints (10 of them exhibit stops), altitude = local terrain max (`terrainH`, ±5×±3-cell window over `TERRAIN` heightmap) + `JCLEAR` (default 7), passed through a ±9-sample moving max (climb *before* hills) and 3 box-smooth passes, clamped to never dip below the safe height — collision-free by construction (validated numerically against the data). `pathPos(s)` is arc-length parameterized; `poseAt(s)` gazes `LOOK_AHEAD_U` (16 units) down-path with pitch clamped to ~11°–30° so every stop frames the landscape consistently. Content lives in the `JOURNEY` array (marked `EDIT YOUR CONTENT HERE`): per stop `{id,label,title,body,media:[{src,caption}],links:[{href,label}]}`.

**UI state machine** (`uiState`):
- `overview` — free orbit via `OrbitControls`, as before.
- `entering` — flies from the current camera pose to a stop's pose (duration scales with distance).
- `journey` — two sub-modes (`jMode`): `docked` (holding a stop: idle breathing drift, hint visible; in assemble mode free 360° drag-look + facet firing, scroll charges the departure bar; in panel mode the classic damped mouse-look ±~30°/±17° where drag *or* scroll charges departure; 650 ms dock cooldown swallows trackpad inertia) and `flying` (eased arc-length flight along the path, damped quaternion follow, slight FOV stretch). Rail dots and arrow keys also travel; Esc exits to free roam; scrolling past either end gives a soft rebuff bounce.
- `exiting` — **Free roam** button; returns to the overview framing and re-enables OrbitControls.

**Stop info display** (v23, reworked v26–v27 — dev tools > "Stop Info" dropdown): `assemble` (default) or `panel` (the classic HTML overlay + clamped mouse-look, kept intact). In assemble mode a docked stop is a panorama of **facets** (text blocks / ASCII covers) hung at fixed yaw/pitch around the camera; the visitor has free 360° drag-look (`freeYaw`/`freePitch`, street-view drag; scroll still departs, so panel-mode's drag-to-depart doesn't exist here). Each facet fires when the gaze comes within `F_GAZE_IN` (~23°) and releases past `F_GAZE_OUT` (~35°): its recruits fly staggered quadratic-bezier arcs, swap geometry mid-flight (shared `glyphGeo` cache), and settle as world-anchored content; **every other glyph in that facet's sight corridor is absorbed too** (flies into a random letter, fading as it lands, budget `F_EXTRA_MAX` 2200) **or fades in place** — so content reads on pure black (this replaced the v23 dim-to-0.15). Partitioning happens once per dock (`assembleStop`): items exclusive per facet (nearest to its anchor, reading-order paired), corridor leftovers to the angularly nearest facet — gaze changes just replay cached flights, no per-frame searches. Ordinary stops have one facet dead ahead (auto-assembles on dock — the arrival gaze is centered on it by `assembleStop`, since terrain clearance can hang facets above the flight pitch; layout via `buildStopLayout`). Facet anchors get a needed-height computation (terrain + block clearance) and an elevation cap of ~24° (`Math.tan(0.42)` — anchors push OUT instead of up past that). The **clearing is elliptical, not rectangular** (v27): each facet fades/absorbs every glyph inside a jittered angular ellipse (`Ry/Rp` = block half-extent + 0.15 rad, per-glyph rim jitter + per-glyph fade rates via `fades[].k`), patches may overlap between facets (fades shared, absorb-flights exclusive to the angularly nearest). A stop with a `gallery:` array (the **Case studies** stop, waypoint xf-0.34/yf0.22) adds 6 ASCII covers ringing the visitor at **even 360/7 spacing** (earlier ±170° spread put buses/food only 20° apart) **sharing one standardized ring height** (max zNeed across facets — validated: ringZ 30.1, all covers level at +24° pitch, f=1.0). `ASCII_COVERS` (~11KB) is generated **offline** by `gen_covers.py` (34-col grids, ramp `' .:-=+*#%@'`, bright paper covers auto-inverted so ink glows, cells colored by luminance via `setImgColor`). **The develop** (v27): ~0.45s after a cover finishes assembling (`PHOTO_DELAY`), the real front page fades in as an 8-column grid of textured tiles (`buildPhotoTiles`, staggered `PHOTO_STAGGER/TILE_MS`, placed 0.35 behind the glyph plane) while the image glyphs dissolve; the title stays as glyphs; looking away folds the photo up fast and everything scatters home (repeatable). Textures come from `COVER_PHOTOS` — **data-URI JPEGs (512px, ~320KB total, generated offline by `gen_photos.py`)**, because external image files would taint WebGL under file://. The bus cover (`ascii:'buses_art'`) assembles from the pre-made ascii-art variant before developing. Regenerate both embedded blocks after swapping cover images. Budget: gallery needs ~5.3k of the 13,268 glyphs. `disassemble(true)` instant-restores everything (called from `beginIntro`, `genRun`, `assembleStop`); departure animates facets home via the `asmRetired` list. The HTML panel drops to a `mini` bottom dock with media thumbnails + link buttons (the gallery stop carries all six report PDFs there). Media images and PDFs live in `images/` and `pdfs/` (from the old `portfolio-main` site, which also supplied the stop content). The journey is now **7 stops** (welcome, profile, Orange Wheel, startups, case studies, skills, contact) — the old separate case stops' waypoints remain as plain path points, so the flight path is unchanged.

**Stop markers: none** (removed across v24–v25 at the user's request as wayfinding clutter). The v20 beacon system — numbered text plaques *and* the additive light pillars/beams — plus the breadcrumb path dots are all gone, along with their helpers (`makeSignTexture`, `roundRectPath`, `pickPlaque`/the plaque raycaster, `buildCrumbs`, `buildBeacons`, `syncJourneyPalette`, `BEAM_TEX`) and the "Path dots" dev toggle. **The flight path itself is unchanged** — only the visual overlays came off. Arrival at a stop is announced solely by the assembled text (or the HTML panel); stops are reached via scroll/drag, arrow keys, and the rail list.

**Intro reveal** (the `surface` load animation): on load, all glyphs start at scale 0. A multi-seed flood fill (Game-of-Life-style, 8-neighbor Moore neighborhood over the real sparse grid, randomized branch order + jitter + occasional early "sparks") assigns each glyph a delay, so the portrait spawns into existence organically rather than as a uniform ripple. Runs once, self-terminates. (The default load animation is now `progressive-soft` — see the intro/animation notes above.)

**Dev tools**: gear icon (bottom-left) opens a panel for live-tweaking bloom strength/radius/threshold, FOV, fog near/far, vignette toggle, journey **Path Height** (rebuilds the path live), **Load Animation** and **Stop Info** dropdowns. A **Raw (no processing)** toggle (v19) bypasses every layer added on top of the grainrad export — the whole EffectComposer/bloom path (frame loop falls back to `renderer.render`), ACES tone mapping, fog (`scene.fog=null`; `sceneFog` keeps the tuned object), vignette, and the `#e8ecf3` tint (pure `#ffffff` instead) — reproducing the raw generator scene's look. The composer renders into a 4× multisampled half-float target, because EffectComposer otherwise drops canvas MSAA and visibly aliases glyph edges.

## Conventions from this project's history

- Always validate camera-math/data-dependent changes (distances, fog thresholds, grid spacing, flood-fill reachability) against the real embedded `asciiData` using a quick script before shipping (Node is not installed on this machine; Python 3.11 is available as `python`) — this file can't be rendered/tested in a browser from here, so number-checking against real data is the substitute for visual QA.
- After any change, report clearly what to check when the user opens it in a real browser, since WebGL behavior can't be verified in this environment.
